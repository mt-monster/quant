# 并发上限实测（续）：4 方并发确认 L ≥ 4（2026-07-25 01:40 GMT+8）

> 承接 `probe_concurrency_report_20260725_0127.md`（已证 L≥3）。用户确认"需要"继续钉精确上限，故拉起**第 4 个**主账号并发任务验证 L≥4。

## 实验设计
- 在 V44 + V45（2 个常驻主账号任务）仍在跑的基础上，同时拉起 **2 个探针实例**（PROBE_TAG=4a / 4b），使主账号同时有 **4 个 multi-sim 在飞**（V44 + V45 + 4a + 4b = 第 3、第 4 个并发）。
- 探针脚本已支持多实例：每个实例写独立 checkpoint（`probe_concurrency_{TAG}_checkpoint.json`）与 PID 文件，互不覆盖。
- 每实例 8 批 × 8 表达式 = 64 个子模拟；提交即占槽、轮询维持并发；遇 HTTP 429 立即 `exit(42)` 关停（本实验未触发）。

## 实测结果
| 探针 | 批次 | HTTP 状态 | any_429 | 说明 |
|---|---|---|---|---|
| 4a | 0–7 | **全 201 OK** | False | 8 批零 429 |
| 4b | 0–7 | **全 201 OK** | False | 8 批零 429 |

- **合计 16 批 / 128 个子模拟，在 4 方并发下全部被平台接受，零 429。**
- **V44/V45 未受拖累（次级争用信号）**：
  - V44：推进至 160/200（80%），avg 59.41s（对比基线 59.25–59.49s，**几乎不变**）；
  - V45：推进至 96/320（30%），avg 56.9s（仍在自然方差内）。
- 探针进程已正常退出；精确核查确认无 python 探针残留（wmic `like` 误匹配的 5 个 PID 实为启动用的 bash 包装进程，非探针本身）。

## 结论
1. **平台真实并发上限 L ≥ 4**。第 4 个并发主账号 multi-sim 被平台接受，且 V44/V45 零退化。
2. 用户"平台限制不是 2 槽"的假设**已被 decisively 证实**——实测可达 **≥4 个并发 multi-sim**，远超最初"勿超 2"的保守估计。实际工作中可安全并行至多 4 个主账号回测任务。
3. **精确 L 仍未确定**（可能是 4 / 5 / 6 …）。`wd_lib_wrapper.py` 的 `Semaphore(5)` 是客户端侧并发上限，与平台 L 无关；平台 L 由 HTTP 429 实际执行，且 429 警告走控制台不进进度日志（故探针改用直接捕获自身提交状态码）。
